# 02 · Архитектура

## Из чего состоит
Одно Next.js-приложение (TypeScript, React). Внутри него три части:
- **Форма** `/` — публичная для сотрудников с корпоративной почтой.
- **Кабинет** `/admin` — список, фильтры, экспорт; только для email из списка админов.
- **API** (route handlers) — приём фидбека, загрузка файлов, выдача списка, CSV.

Данные: **PostgreSQL**, две таблицы — `feedback` и `attachment`.
Файлы: на диск сервиса (том `uploads/`), в базе только путь. Наружу ничего не уходит.
Авторизация: **Google OAuth** через Auth.js, сессия в httpOnly-cookie, домен проверяется на сервере.

## Схема данных
`feedback`: id · author_email · section · text · created_at
`attachment`: id · feedback_id · filename · mime · size · path

Раздел и список админов — в конфиге (`config/app.ts`), правятся кодом.

## Где дорого и как дешевле
Дорого было бы: своя система ролей, свой загрузчик файлов в облако, аналитический дашборд.
Дешевле: список админов строкой в конфиге, файлы на диск, аналитика — выгрузкой в CSV.

## Где окажется результат
Docker-образ + `docker-compose` (приложение + Postgres + том для файлов), разворачивается
внутри контура компании. Локально — одна команда `docker compose up`.

## Проверки безопасности, которые обязаны быть в коде
- Домен почты проверяется на сервере, не в браузере.
- Список админов проверяется на сервере при каждом запросе к кабинету и к API кабинета.
- Тип и размер файла проверяются на сервере; имя файла не используется как путь.
- Файлы отдаются только авторизованным, через свой обработчик, а не как статика.
