# 02 · Архитектура

## Из чего состоит
Одно Next.js-приложение (TypeScript, React). Внутри него три части:
- **Форма** `/` — публичная для сотрудников с корпоративной почтой.
- **Кабинет** `/admin` — список, фильтры, экспорт; только для email из списка админов.
- **API** (route handlers) — приём фидбека, загрузка файлов, выдача списка, CSV.

Данные: **PostgreSQL**, две таблицы — `feedback` и `attachment`.
Файлы: на диск сервиса (том `uploads/`), в базе только путь. Наружу ничего не уходит.
Аутентификация: **свою не делаем** — берём готовую идентичность из контура (см. следующий раздел).

## Кто вошёл: один адаптер, две реализации
Сотрудник приходит по ссылке из план-факта, уже войдя в контуре. Второго логина быть не должно,
поэтому источник идентичности прячем за **одну функцию** `getCurrentUser(): { email } | null`.
Реализация выбирается флагом `AUTH_MODE` в `config/app.ts` — остальной код о ней не знает.

- `AUTH_MODE=proxy` (**основной**). Идентичность даёт SSO-шлюз контура. Предпочтительно —
  подписанный JWT (`Cf-Access-Jwt-Assertion` / `Authorization: Bearer`), подпись проверяем по JWKS.
  Если шлюз умеет только голый заголовок (`X-Auth-Request-Email`, `X-Forwarded-User`,
  `Remote-User`) — принимаем его **только** при выполненной изоляции (см. проверки).
- `AUTH_MODE=google` (**резерв**). Свой Google OAuth через Auth.js, сессия в httpOnly-cookie.
  Настраивается как silent SSO: `hd=<домен>`, `login_hint`, без `prompt=consent`, приложение
  помечено доверенным в Workspace — тогда вход проходит редиректом, без экранов.
- `AUTH_MODE=dev` — подстановка почты из `DEV_USER_EMAIL` для локальной разработки.
  Приложение **падает на старте**, если этот режим включён при `NODE_ENV=production`.

Почему так: реализация зависит от ответа инфраструктуры, которого пока нет, а код нужно писать
сегодня. Абстракция стоит одну функцию и убирает OAuth-клиент в Google Workspace с критического
пути — он был единственным реальным риском для срока.

**VPN аутентификацией не считаем.** Он говорит «трафик из нашей сети», но не говорит, кто человек.
Почта автора нужна по делу: через месяц, собирая топ-5 проблем, мы должны иметь возможность
вернуться к автору с вопросом.

## Схема данных
`feedback`: id · author_email · section · text · created_at
`attachment`: id · feedback_id · filename · mime · size · path

Раздел и список админов — в конфиге (`config/app.ts`), правятся кодом.

## Где дорого и как дешевле
Дорого было бы: своя система ролей, свой загрузчик файлов в облако, аналитический дашборд,
своя аутентификация с паролями.
Дешевле: список админов строкой в конфиге, файлы на диск, аналитика — выгрузкой в CSV,
личность — от шлюза контура.

Отдельно про то, чего мы **не** делаем: не читаем cookie план-факта (чужой домен, чужой секрет),
не принимаем токен в query-параметре (утечка в историю, `Referer`, логи и скриншоты) и не просим
команду план-факта выдавать нам подписанные тикеты (корректная схема, но это чужой релиз внутри
нашего однодневного срока). Ссылкой из план-факта передаём только безопасный контекст:
`?section=` (сверяем со списком из конфига) и `?from=` (с какого экрана пришёл).

## Где окажется результат
Docker-образ + `docker-compose` (приложение + Postgres + том для файлов), разворачивается
внутри контура компании. Локально — одна команда `docker compose up`.

## Проверки безопасности, которые обязаны быть в коде
- **Заголовку с почтой доверяем только при выполненном условии.** Либо это подписанный JWT
  и мы проверили подпись, либо приложение недоступно напрямую в обход прокси (слушает только
  сеть прокси) **и** прокси перезаписывает заголовок, а не дополняет. Иначе любой сотрудник
  пришлёт `X-Auth-Request-Email` с чужой почтой и оставит фидбек от имени руководителя.
- Домен почты проверяется на сервере, не в браузере. Шлюз может пускать в контур подрядчиков
  и гостей — «прошёл шлюз» не равно «наш сотрудник».
- Почта берётся **только** из результата `getCurrentUser()`. Ни query-параметр, ни поле формы,
  ни присланный клиентом токен источником личности быть не могут.
- Список админов проверяется на сервере при каждом запросе к кабинету и к API кабинета.
- Тип и размер файла проверяются на сервере; имя файла не используется как путь.
- Файлы отдаются только авторизованным, через свой обработчик, а не как статика.
- `AUTH_MODE=dev` в продакшене — не предупреждение, а отказ старта.
