# Сбор фидбека по план-факту

Внутренний сервис: сотрудники оставляют фидбек по новому план-факту, команда продукта читает
его в кабинете и выгружает в Excel или CSV. Приватный репозиторий, все документы внутренние.

## Что здесь

| Файл | Что это |
|---|---|
| [`04-прототип.html`](04-прототип.html) | **Кликабельный прототип** на моковых данных: две роли, сценарии, включая отказы. Открывается двойным кликом, без сервера |
| [`03-для-разработчиков.html`](03-для-разработчиков.html) | Техспека на один разговор с разработкой: зоны решений, схема данных, режимы входа, чек-лист безопасности |
| [`02-архитектура-разбор.html`](02-архитектура-разбор.html) | Та же архитектура простым языком: путь одного фидбека, схема таблиц, глоссарий |
| [`02-архитектура.md`](02-архитектура.md) | Архитектура: состав, вход из контура, схема данных, обязательные проверки безопасности |
| [`01-импакт-и-идея.md`](01-импакт-и-идея.md) | Импакт, граница v1 и **8 замороженных acceptance criteria** |
| [`ЖУРНАЛ.md`](ЖУРНАЛ.md) | Хронология решений: что сделано, что решено и почему, открытые вопросы |

Кода сервиса пока нет: он начинается после встречи с разработкой — от неё зависят стек,
место для базы, деплой и режим аутентификации.

## Прототип

Шапка переключает роль (**Юзер · форма** / **Админ · кабинет**), под ней сценарии — счастливый
путь и отказы. Живое: валидация формы, вставка скриншота из буфера обмена, счётчики по разделам,
фильтры и сортировка, выгрузка `.xlsx` и `.csv`.

Прототип **не** содержит аутентификации и ничего не сохраняет: он про экраны и формулировки,
не про архитектуру. Разделы, список админов и моковый фидбек лежат в начале скрипта.

## Границы v1

Входит: форма, кабинет просмотра, фильтры и сортировка, выгрузка, скриншоты, список админов.
Следующий заход: статусы и теги обработки, комментарии команды, дашборд аналитики,
«свои обращения» для сотрудника, встраиваемый виджет.
